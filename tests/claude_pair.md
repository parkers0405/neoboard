# Claude Code: pair from a pasted prompt

For the parent CLI/UI: emit an ordinary instruction to run the existing `neoboard wake pair --request <handle>` command **in this conversation’s local Bash tool**, with the trusted executable path quoted for that shell. Supply neither an ID nor `--session`. In `wake::target`, use `CLAUDE_CODE_SESSION_ID` from the command’s environment for harness `claude`, reject conflicting identity inputs, and retain exact UUID and runtime path validation. Do not search transcripts, select the latest chat, or enable wakes as part of pairing. No Claude-specific Rust module, slash command, skill installation, or profile edit is needed on the verified version.

On POSIX, run `cargo build --locked --bin neoboard --bin neochatd` followed by `python3 -B tests/claude_pair_acceptance.py`. Use `--claude /absolute/path/to/claude` or `--board-bin-dir /path/to/binaries` if needed. The test requires an installed CLI; it does not substitute a shell or runtime fixture if Claude is absent.

The drill uses a fresh home, profile, board, workspace and loopback Messages provider. A genuine Bash call first checks that `CLAUDE_CODE_SESSION_ID` matches the CLI’s own result. The same pairing request fails outside a conversation. A new chat receives the ordinary pairing text as its first user message. While that chat is waiting on the provider, a newer decoy chat runs in the same workspace/profile. The real Bash tool then runs only the exact allowed pairing command under `dontAsk`; status must show the original chat’s UUID and wake Off. No test input supplies a session ID, no transcripts are inspected, and no external model, board, keychain, or login service is needed.

Verified with Claude Code 2.1.330 on macOS. This is `--print` text input with a deterministic provider, not a GUI clipboard test or a claim about model compliance. `--bare` disables user hooks and keychain reads. On clients that do not expose the variable, fail closed; tell the user to use a supported local Claude Code version or an independently verified exact ID. Claude’s skill-template substitutions and SessionStart hooks are separate opt-in mechanisms, not expansions of ordinary pasted text; no such fallback is installed or tested here. See the [skills reference](https://code.claude.com/docs/en/skills) and [hook reference](https://code.claude.com/docs/en/hooks).

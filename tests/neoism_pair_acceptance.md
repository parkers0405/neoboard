# Neoism native pairing drill

This drill requires both the NeoBoard CLI with `wake::neoism_pair::resolve` wired into `pair()` and the patched local Neoism server. The upstream base is Neoism `v0.7.167` (`c3546916fc6e22783c80749cfe3e04434253f339`); the base **without the patch** does not implement the handoff. A version string alone cannot identify a compatible binary. The previously tested `0.7.164` binary only supports the explicit/manual pairing flow.

From the Neoism checkout, build `cargo build --locked --offline -p neoism-agent`. From NeoBoard, build `cargo build --locked --offline --bin neoboard --bin neochatd`. Run `python3 -B tests/neoism_pair_acceptance.py --neoism-agent ../neoism/target/debug/neoism-agent`. Use `--board-bin-dir` for nondefault CLI paths. No installs, profile discovery, daemon restart or service registration is needed for the drill.

The offline provider receives the ordinary desktop pairing text and emits a real `bash` tool call. The fixture creates the intended conversation and a newer decoy; the driver knows their IDs to send and independently observe turns, but supplies no ID in the successful pasted prompt or shell command. An ordinary terminal cannot claim the request; a decoy with a conflicting explicit ID cannot consume it. The intended chat pairs Off. A queued mention generates no turn while Off and reaches only the target after explicit enable. The provider checks its inputs for fixture secrets, and the controller exercises credential-scope denials without sending those credentials to the model.

## Runtime contract

`BuiltinTool::execute` already has the invocation's session ID and loads its exact session scope. The `bash` process launcher, however, only had a cached login-shell environment and the invocation env. Neither an MCP connection, the shell's cwd, a global server variable nor the latest session establishes which conversation issued that tool call. The patch uses the actual bound listener in that `AppState` and the authorized `ToolContext`, not those alternatives. It never changes the login-shell cache or process-global environment.

For local native shell pairing the host supplies `NEOISM_WAKE_HANDOFF_V1` privately to the child. The value is a temporary file path, **not a bearer**. The file is scoped to the invocation and unlinked when the call returns/cancels. On POSIX the file is created private; the reader rejects symlinks, non-regular files, oversized files, wrong owner and nonprivate mode. A trusted local OS user/workspace and genuine NeoBoard executable are assumed; this is not a security boundary against a malicious same-user shell. The pending request remains single-use. The scoped credential is saved only with the private binding, not in provider inputs, printed commands or tool results.

The server uses a domain-separated HMAC of the actual loopback listener and exact session ID. It accepts the result only for the session GET and a bounded text-only `prompt-if-idle` POST, under ordinary session authorization/control checks. It is not a daemon signing key or an operator token. The local runtime needs an existing agent token or daemon signing secret of at least 16 bytes. No on-disk daemon credential is discovered. Key/port changes invalidate the delegation; no replacement server, latest conversation, token discovery or automatic new binding is attempted. This does not add authentication to a server explicitly configured to allow other unauthenticated clients.

Automatic pairing is for native POSIX local, non-tenant sessions with a real loopback listener; hosted, worker, listener-free embedded and external-provider shells are not covered. Windows fails closed until it has a verified private-ACL transport; explicit pairing from a trusted operator shell remains available. For a deployed Neoism app, rebuild/package the **actual listener owner** against the patched `neoism-agent-server`. In particular `neoism-workspace-daemon` links that library; replacing a standalone CLI next to an old in-process server does not upgrade dispatch. A planned restart of the updated listener is required for existing desktops to use the feature. No live install/restart is part of this test.
